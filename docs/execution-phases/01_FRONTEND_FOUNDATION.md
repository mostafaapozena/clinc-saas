# المرحلة 1 — إكمال أساس الواجهة
الحالة عند إعداد الخطة: جاهزة للبدء. الهدف: تثبيت الشكل والسلوك الحاليين، لا إعادة تصميم الهوية.

## ما نعتبره موجودًا ونحتاج تأكيده
PRs #34–#38 مدمجة وفق التقرير: سجل وحدات واحد، مكونات data، مخزون تجريبي مرحّل، تواريخ، تأكيدات، إعدادات غير محفوظة، axe، معرض تطوير وقواعد PR.
الباقي المقاس: 33 جدولًا خامًا/3 DataTable، 81 form-actions/صفر ActionBar، 12 مرشحًا خامًا، 7 useMoney، 47 محدد CSS مكرر، ملف مشغّل 1943 سطرًا. هذه أرقام خط أساس وليست مستهدفًا أعمى لتصفير كل استخدام HTML.

## دخول المرحلة
قراءة جرد المرحلة صفر وتأكيد main والتغييرات الجارية. الاحتفاظ بالوظائف والصلاحيات والهوية المعتمدة. أنشئ crosswalk إلى P1-01…P1-13 الأصلي؛ المعرفات التالية محلية ولا تعادل الأصل تلقائيًا.

## ملاحظات صاحب المشروع الملزمة
الخط العربي يبدو كبيرًا في أجزاء؛ راجع سلم أحجام وكثافة النص في السياق، لا تصغّر كل شيء عشوائيًا. ثبّت line-height والتفاف النص وأحجام الأزرار والفجوات بين الأيقونة والكلام.
تبويبات التقارير تبدو كحلقة تمرير لا تنتهي بالعربية والإنجليزية: أعد إنتاج المشكلة وحدد CSS/JS/RTL/overflow؛ لا تفترض السبب. إذا كثرت الفئات استخدم تصنيفًا رئيسيًا مع تنقل فرعي واضح بدل شريط طويل مربك؛ حافظ على deep links وحالة التصفية.
الرسوم تخدم السؤال والبيانات: لا donut للزينة، ولا رسوم وهمية. أظهر الوحدة والفترة والنطاق ومصدر القيمة، مع بديل جدولي.
تجنب أعمدة نص ضيقة تكسر الاسم والبريد حرفًا حرفًا، وأزرارًا بأحجام مختلفة في المجموعة نفسها. اللمس على الجوال مناسب مع focus واضح.
فلترة اليوم بالفرع تغيير backend محدود داخل النطاق؛ حافظ على حدود صلاحيات الفروع، ولا تعتبر نص «كل الفروع» حلًا دائمًا إذا كان global scope يفترض شمول الصفحة.

## خارج النطاق
لا HR أو شيكات أو معالجات إعداد جديدة، لا تغيير سياسات clinical lead أو الاعتماد السريري، لا مزود دفع أو إعادة تسمية المنتج.

## التحقق ومعيار الإغلاق
فحص العربية والإنجليزية والفاتح والداكن، 360/390/768/1024/1366/1920، وتكبير 200% فعليًا. لا horizontal overflow على الصفحة؛ التمرير داخل جدول عريض استثناء موثق.
مالك/مدير/طبيب/استقبال/محاسب/مطّلع، والمشغّل admin/support وفق الحسابات الفعلية. axe ومسار لوحة مفاتيح وفحص قارئ شاشة حيث يتاح؛ لا تدّع المنفذ عند غياب البيئة.
Chromium مع رحلات مستهدفة Firefox/WebKit، وتواريخ date-only مقابل instants وتوقيت العيادة. لا تتغير قيم الأموال أثناء التحميل.
npm run verify وCI على commit المقدم. كل نمط خام باقٍ له تبرير؛ الترحيل ليس استبدالًا نصيًا لكل table.
الإغلاق يتطلب عدم وجود عيب مؤثر في النطاق أو وضع تحقق مفقود مؤثر تحت «مكتمل». قدم تقرير الفرق واللقطات والمكونات المعتمدة والاستثناءات ورابط المعاينة وcommit. دمج فقط وفق تفويض الجلسة وحماية الفرع؛ وإلا PR جاهز للمراجعة.
## قواعد ملزمة عند التنفيذ
- هذا ملف تخطيط معتمد على تقرير المرحلة صفر الذي أرسله المالك، وليس فحصًا مستقلًا للكود. خط الأساس المبلّغ: main عند 74ad659؛ وثائق المرحلة صفر في PR #39، commit 621de78. تحقق من الحالة الحالية قبل العمل ولا تعد تنفيذ المكتمل.
- اقرأ تعليمات المشروع وdocs/delivery-plan/ أولًا. هذه الملفات تنظم التنفيذ ولا تمحو الأدلة التاريخية. سجل أي تعارض مع السبب والدليل.
- حافظ على الهوية المعتمدة: raclinic منتج Devware، العربية RTL وAlexandria، الإنجليزية LTR وInter، فاتح/داكن/حسب الجهاز.
- نفّذ مرحلة واحدة فقط. الأفكار الجديدة في قائمة انتظار؛ لا توسّع النطاق تلقائيًا. الأعمال المستقلة داخل المرحلة يمكن توزيعها بين الفريق.
- الأدوار المقترحة وظائف عمل وليست افتراضًا لوجود موظفين إضافيين. عيّن مسؤولًا ومراجعًا لكل مهمة عند بدء المرحلة.
- لا تغيّر صلاحيات سريرية أو سياسة مالية أو تسعيرًا كأثر جانبي لتحسين الواجهة. API هو مرجع التفويض؛ إخفاء الرابط لا يكفي.
- التطوير والتحقق في Codespace؛ لاحقًا النشر إلى staging عبر إصدارات محددة، وليس تعديل كود مباشر على الخادم.
- بيانات تجريبية فقط حتى اجتياز شروط التشغيل الحقيقي. لا أسرار في Git أو التقارير أو لقطات الشاشة.
- اعمل باستقلالية في القرارات الروتينية المصرح بها، مع احترام صلاحيات الأدوات وحماية الفروع. لا force push أو تجاوز CI.
- احفظ التقدم في سجل التنفيذ. الحالة: لم تبدأ / قيد التنفيذ / قيد المراجعة / مكتملة ومتحقق منها / متوقفة بسبب محدد.
- لا تدّع تحققًا لم تنفذه. افصل نتيجة اليوم عن الدليل التاريخي، والمحاكاة عن التكامل الحقيقي.
- الإغلاق: كود ومراجعة واختبارات مناسبة وفحص واجهة وتوثيق وأدلة على نفس commit. لا تبدأ المرحلة التالية تلقائيًا.
