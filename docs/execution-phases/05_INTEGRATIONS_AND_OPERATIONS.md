# المرحلة 5 — التشغيل والتكاملات والسعة
## الوضع
الدفع والبريد محاكيات؛ التكاملات الحقيقية 0/8 وبوابات الإنتاج 0/14 وفق تقرير الجرد. MFA ومراقبة ونشر غير مبنية، الاستعادة محلية غير مجدولة.
اختبار حِمل سابق حتى 120 طلب/ثانية على جهاز مشترك ليس شهادة 10 آلاف مستخدم.

## 5A — مسار مبكر: staging على VPS
التوقيت: بعد إغلاق 1 وتوفر الخادم، قبل 2 إن أمكن. لا ينتظر كل وظائف ERP ولا يجيز بيانات مرضى حقيقية.
المطلوب من المالك: خادم/صلاحية مناسبة ودومين أو subdomain وميزانية ومكان استضافة. الأسرار عبر قناة آمنة وبيئة الخادم، لا داخل الملف أو المحادثة أو Git.
المهام:
1. فحص الموارد والنظام والخدمات القائمة قبل تغيير شيء؛ لا تمسح خادمًا مستخدمًا.
2. فصل staging config/database/accounts عن أي إنتاج. HTTPS وreverse proxy وعدم كشف Mongo أو منافذ الإدارة للإنترنت.
3. تشغيل إصدار مبني معلوم commit بإدارة عمليات/حاويات وسياسة restart وفحص صحة؛ لا Vite dev server كاستضافة دائمة.
4. جلسات وcookies وCSRF وorigin/proxy settings سليمة، وصول مقيد للبيئة وnoindex وعدم الاكتفاء به للحماية.
5. بقاء المحاكيات موسومة بوضوح، منع الصرف/الإرسال الحقيقي غير المصرح. طريقة وصول لصندوق بريد التطوير مقيدة.
6. نسخ قبل migration، تجربة استعادة مناسبة، سجل نشر وخطة رجوع لا تفترض أن الرجوع للكود يعكس تغييرات البيانات.
7. تحديثات عبر Codespace → Git/CI → release محدد → staging؛ لا تطوير مباشر على VPS.
القبول: رابط ثابت مع HTTPS، signup جديد لكل تخصص، إنشاء منشأة واستئنافها وفتح dashboard، API سليم وإعادة تشغيل الخدمات لا يفقد البيانات، وثيقة نشر وتحديث وتراجع.
توقف 5A بعد التسليم وارجع للمرحلة المقررة.

## 5B — التكاملات
جرد الثمانية بأسمائها من docs/delivery-plan، لا تخترعها من العدد. مزود دفع مختار مع sandbox واختبار توقيع وإعادة webhook وتكرار وترتيب ومطابقة وإلغاء؛ إعداد طريقة دفع ليس تكاملًا.
مزود بريد ودومين SPF/DKIM/DMARC ودعوات واستعادة وتأكيد وتسليم/فشل وإعادة محاولة. SMS/WhatsApp فقط إذا اعتمدت حاجة ومزودًا؛ ليست شرطًا عامًا لكل استخدام.
MFA وتسجيل الأجهزة واسترجاع آمن وفق سياسة معتمدة، خاصة المشغّل والأدوار الحساسة.
## 5C — العمليات وحماية البيانات
استضافة وإقامة بيانات وسياسات قانونية واحتفاظ وحدود اشتراك واضحة، مراقبة وتنبيه خارجيان، نسخ مشفرة خارج الخادم بجدول وRPO/RTO معتمدة وتمرين استعادة، إدارة أسرار وتحديثات واعتمادات واختبار اختراق وإغلاق النتائج المؤثرة.

## 5D — السعة والاعتمادية
حدد هدفين منفصلين: عدد حسابات مسجلة/منشآت، وعدد مستخدمين نشطين ومتزامنين في ساعة الذروة. 5 آلاف أو10 آلاف حساب لا تساوي طلبات متزامنة.
اكتب workload واقعيًا بمدة تفكير ومزيج قراءة/كتابة وعيادات كبيرة وأدوار، مع SLOs مقترحة يعتمدها المنتج قبل القياس: p95/p99، خطأ، حجز متعارض، زمن مهمة.
افصل API وMongo ومولد الحمل قدر الإمكان، اختبر أكثر من نسخة على أجهزة مناسبة وفشل نسخة ومخزن limits وضغط الذروة واختبارًا ممتدًا. لا تولد حملًا على بيئة مشتركة دون حدود حماية.
وثق CPU/RAM/IO وخطط الاستعلام وحدود كل مورد وتكلفة البيئة ونقطة التشبع. لا حاجة microservices بلا سبب مقاس.

## الإغلاق
كل بوابة إنتاج من الجرد لها مالك ودليل وحالة. يجوز الاستغناء عن تكامل اختياري بتعليل وبقرار واضح مع ضبط وعد المنتج؛ لا شطب بوابة أمان لازمة لتحسين النسبة.
لا إعلان جاهزية إنتاج قبل قبول السياسات والمراجعات والنتائج. staging نجاح نشر فقط وليس قبول تشغيل حقيقي.
## قواعد ملزمة عند التنفيذ
- هذا ملف تخطيط معتمد على تقرير المرحلة صفر الذي أرسله المالك، وليس فحصًا مستقلًا للكود. خط الأساس المبلّغ: main عند 74ad659؛ وثائق المرحلة صفر في PR #39، commit 621de78. تحقق من الحالة الحالية قبل العمل ولا تعد تنفيذ المكتمل.
- اقرأ تعليمات المشروع وdocs/delivery-plan/ أولًا. هذه الملفات تنظم التنفيذ ولا تمحو الأدلة التاريخية. سجل أي تعارض مع السبب والدليل.
- حافظ على الهوية المعتمدة: raclinic منتج Devware، العربية RTL وAlexandria، الإنجليزية LTR وInter، فاتح/داكن/حسب الجهاز.
- نفّذ مرحلة واحدة فقط. الأفكار الجديدة في قائمة انتظار؛ لا توسّع النطاق تلقائيًا. الأعمال المستقلة داخل المرحلة يمكن توزيعها بين الفريق.
- الأدوار المقترحة وظائف عمل وليست افتراضًا لوجود موظفين إضافيين. عيّن مسؤولًا ومراجعًا لكل مهمة عند بدء المرحلة.
- لا تغيّر صلاحيات سريرية أو سياسة مالية أو تسعيرًا كأثر جانبي لتحسين الواجهة. API هو مرجع التفويض؛ إخفاء الرابط لا يكفي.
- التطوير والتحقق في Codespace؛ لاحقًا النشر إلى staging عبر إصدارات محددة، وليس تعديل كود مباشر على الخادم.
- بيانات تجريبية فقط حتى اجتياز شروط التشغيل الحقيقي. لا أسرار في Git أو التقارير أو لقطات الشاشة.
- اعمل باستقلالية في القرارات الروتينية المصرح بها، مع احترام صلاحيات الأدوات وحماية الفروع. لا force push أو تجاوز CI.
- احفظ التقدم في سجل التنفيذ. الحالة: لم تبدأ / قيد التنفيذ / قيد المراجعة / مكتملة ومتحقق منها / متوقفة بسبب محدد.
- لا تدّع تحققًا لم تنفذه. افصل نتيجة اليوم عن الدليل التاريخي، والمحاكاة عن التكامل الحقيقي.
- الإغلاق: كود ومراجعة واختبارات مناسبة وفحص واجهة وتوثيق وأدلة على نفس commit. لا تبدأ المرحلة التالية تلقائيًا.
